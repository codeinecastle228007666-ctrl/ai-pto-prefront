# Задачи: переход с моков на живой бэк

Контекст и расхождения: [переход-с-моков-на-бэк.md](переход-с-моков-на-бэк.md). Контракт: `AI-PTO-BACK/docs/openapi.yaml`.
Фронтенд опирается на него, при расхождении правится фронтенд или контракт, решение принимается в задаче 0.

## 0. Контракт (до остального)

Сделать
- [ ] Выбрать источник правды между `docs/openapi.yaml` и `docs/openapi/openapi.yaml`, второй удалить или пометить устаревшим.
- [ ] Выровнять `src/common/dto/openapi.types.ts` с выбранным контрактом: `Finding` (`sources`, `expected`, `actual`, `normRef`, `explanation`), `PackageCreated.uploads` (`headers`, `uploadUrl: null` у дубликата), `ExtractedField` (`label`, `source`).
- [ ] Зафиксировать в контракте, что порядок `uploads` равен порядку `files` в запросе.
- [ ] Решить форму `GET /reports/{id}/download`: бинарный PDF или `{url}`.
- [ ] Решить, где лежит чек-лист: `/objects/{id}/checklist?packageId=` или `/packages/{id}/checklist`.
- [ ] По правилу AGENTS.md сначала предложить diff для `openapi.yaml`, потом менять.

Не делать: менять эндпоинты и поля без подтверждения.

Готово, когда: в репозитории один контракт, типы бэка с ним совпадают, фронтенд проверен на отсутствие расхождений.

## 1. Бэкенд: хранилище и пакеты

Сделать
- [ ] Добавить S3-клиент (согласовать зависимость), настройки в `.env.example` и `docker-compose` (endpoint, бакет, ключи).
- [ ] CORS бакета MinIO: `PUT`, заголовок `Content-Type`, origin фронтенда.
- [ ] `POST /objects/{id}/packages`: проверка формата (415), размера (413), `minItems/maxItems` (422), создание `Package` и `Document` на каждый файл, presigned PUT и `headers` в ответе, дубликат по `sha256` внутри организации даёт `duplicateOf` и `uploadUrl: null`.
- [ ] `GET /objects/{id}/packages`.
- [ ] `POST /packages/{id}/start`: 409, если не все файлы загружены (дубликаты считаются загруженными), идемпотентность, постановка задач в очередь.
- [ ] `GET /packages/{id}`: статус, `progress`, документы с `stages` и счётчиками замечаний.
- [ ] `GET /documents/{id}/file`: временная ссылка на оригинал.
- [ ] Все выборки ограничены `organizationId` из сессии, чужой id даёт 404.

Не делать: пайплайн обработки.

Готово, когда: во фронтенде с `VITE_USE_MOCKS=false` файлы загружаются на странице `/objects/:id/upload`, пакет создаётся, `start` проходит, страница пакета показывает документы, оригинал PDF открывается.

## 2. Бэкенд: очередь и воркер

Сделать
- [ ] Решить вопрос с Redis: BullMQ из зависимостей убран. Либо вернуть, либо очередь на PostgreSQL (по AGENTS.md согласовать до начала).
- [ ] Отдельный процесс воркера (`yarn start:worker`).
- [ ] Статусы пакета и документа переходят `uploading → queued → processing → done | partial | failed`; ошибка одного файла не роняет пакет (статус `partial`).
- [ ] Результат каждого этапа сохраняется в `DocumentStageRun`, этапы идемпотентны.
- [ ] `needs_ocr` для файла без текстового слоя.

Готово, когда: после `start` статусы документов меняются сами, повторный запуск этапа не создаёт дубликатов.

## 3. Бэкенд: этапы пайплайна

Сделать
- [ ] `extract`: текст и координаты из PDF, DOCX, XLSX, CSV через интерфейс `DocumentParser`.
- [ ] `classify`: тип документа и `typeConfidence`, ручная смена `PATCH /documents/{id}`.
- [ ] `parse`: извлечённые поля `ExtractedField` с `confidence` и `source` (страница и `bbox` в долях от левого верхнего угла).
- [ ] `GET /documents/{id}` и `PATCH /documents/{id}/fields`: `editedManually`, `originalValue`, перезапуск `rules` после правки.
- [ ] `rules`: правила как чистые функции с тестами, `Finding` с `ruleId`, `ruleVersion`, `sources`.
- [ ] `explain`: пояснение через `LlmClient`, ответ валидируется zod.

Готово, когда: на реальном пакете появляются типы документов, поля с подсветкой источника и замечания.

## 4. Бэкенд: замечания, комплект, отчёт, SSE

Сделать
- [ ] `GET /objects/{id}/findings`: фильтры, `items/meta/counts`, по умолчанию последний пакет.
- [ ] `PATCH /findings/{id}`: статус и комментарий, для `dismissed` комментарий обязателен (422), запись в `FindingHistory`.
- [ ] Чек-лист: `GET /objects/{id}/checklist`, расчёт `readiness` и статусов `missing/partial/complete`.
- [ ] Отчёт: `POST /packages/{id}/reports` (409, пока пакет обрабатывается), `GET /reports/{id}`, скачивание PDF.
- [ ] `GET /packages/{id}/events`: SSE с событиями `package.snapshot`, `document.stage`, `package.progress`, `package.done`, snapshot при подключении, авторизация cookie.

Готово, когда: панель замечаний, вкладки «Поля» и «Комплект», кнопка «Отчёт» и прогресс на странице пакета работают без моков.

## 5. Фронтенд при переходе

Сделать
- [ ] Включить `VITE_USE_MOCKS=false`, прогнать сценарий: вход, объект, загрузка, прогресс, замечания, правка поля, отчёт.
- [ ] Сверить реальные ответы с типами в `src/entities/*`, расхождения чинить в типах, а не маппингом.
- [ ] Проверить прогресс по SSE за прокси (нет буферизации, cookie доходит), при недоступности потока работает поллинг.
- [ ] Если `GET /objects` останется без пагинации, решить, когда переносить фильтры на сервер.
- [ ] Обработать реальные ошибки загрузки: 413, 415, истёкший `uploadUrl`, потеря сети.
- [ ] Обновить `.env.example` и README, как запускать с бэком.
- [ ] Решить судьбу моков: удалить или оставить для демо-режима.

Не делать: возвращать маппинг DTO в UI-типы.

Готово, когда: весь сценарий проходит с `VITE_USE_MOCKS=false`, моки не нужны для работы.

## 6. Не вошло в текущую версию фронтенда

- [ ] Смена типа документа (`PATCH /documents/{id}`) и перезапуск проверки (`POST /documents/{id}/recheck`).
- [ ] Удаление документа.
- [ ] История решений по замечанию (`GET /findings/{id}/history`) и массовые решения (`POST /findings/bulk`).
- [ ] Список пакетов объекта (`GET /objects/{id}/packages`) и список отчётов (`GET /objects/{id}/reports`).
- [ ] Сводка по объекту (`GET /objects/{id}/summary`) для обзора.
